# NEXUS 统一交互规范（Interaction Spec）

本规范是 NEXUS 全部视图的交互底线。任何新增/修改功能必须满足以下规则；
验收方式见 `tools/.probe/test-bp-position.cjs`、`test-views.cjs`、`test-functional.cjs`（实机 CDP 驱动）。

## 1. 按钮与操作

- 每个按钮必须有真实功能；禁止「有外观无行为」的占位按钮。
- 每个选择操作必须有即时视觉反馈：选中态（chip/badge/高亮）、槽位闪光、toast 三者至少其一。
- 异步操作必须有加载态（skeleton/「分析中…」）与失败态（错误文案 + 重试按钮）；禁止静默卡死。
- 危险操作（重置/删除/恢复备份）必须二次确认；确认弹窗支持取消、Esc、点击遮罩关闭。

## 2. 筛选与搜索

- 每个筛选条件必须真正影响数据查询（后端过滤），不允许只改界面不改数据。
- 位置筛选以真实 OP.GG 按位置统计为准：
  - 有该位置统计行 → 进入候选并展示该位置胜率/登场/禁用/梯度；
  - 仅官方 meta 标注该位置、无统计样本 → 标记「位置待确认」，排在末尾，不编造数值；
  - 两者皆无 → 不进入该位置候选。
- 多位置英雄按数据出现在多个位置候选中（如格温/瑟提/派克），不写死单位置。
- 搜索在当前筛选范围内生效；切换位置时搜索词保留并给出明确文字反馈（「已切换到 X · 搜索 Y 已保留」）。
- 排序（梯度/胜率/登场/禁用/名称）与梯度筛选、收藏筛选、擅长筛选可叠加，且与后端排序一致。
- 筛选状态（位置/搜索/排序/选中英雄）保存在视图模块级状态中，切换页面再返回时恢复。

## 3. 选人与 BP 联动

- 点击蓝/红方任一路槽位 → 选择器默认该路候选；标题与模式徽章明确当前范围。
- 禁用槽位 → 明确显示「全部位置模式」，可手动切换位置缩小范围。
- 已选/已禁英雄在选择器中置灰并标注原因（已选/已禁），不可重复选择。
- 选人/禁人/撤销/替换/重置后：槽位、计数、阵容分析、对位评估、分路建议全部同步重算。
- 分路建议按空位逐路计算，每路只引用该位置的真实统计；点击建议卡片填入对应位置空槽。
- 推荐考虑：版本/服务器/段位（当前数据筛选）、位置、己方阵容短板、敌方已选克制风险、
  个人英雄池（缓存真实对局）、常用英雄设置、主打位置标记。
- 快速连续切换筛选时以最后一次为准（请求序号守卫），禁止旧响应覆盖新结果。

## 4. 导航与状态

- 页面跳转必须到达正确视图；跳转参数（英雄 key/位置/玩家 puuid）必须被目标视图消费。
- 返回上一页恢复浏览状态：BP 棋盘与撤销历史、强度榜筛选、资料库搜索、出装中心选中英雄、
  玩家中心最近查看的资料（缓存读取，不重复发网络请求）。
- 并发导航守卫：慢加载的旧页面不得覆盖新页面。
- 弹窗嵌套时 Esc 只关闭最上层；关闭弹窗不得重置底层页面状态。

## 5. 数据诚实

- 未连接/未配置/无样本一律如实显示（「尚未配置 · 等待接入」「暂无统计」「位置待确认」），
  禁止伪造连接成功、伪造胜率/登场率/Counter。
- 真实统计（OP.GG/LCU）与启发式推理必须分开标注来源标签。
- 缓存数据必须标注「缓存/非实时」；个人擅长标记必须来自真实缓存对局。

## 7. 测试环境注意

- 本机 CDP 测试禁止 `Emulation.setDeviceMetricsOverride`：会使合成器停摆、
  后续 `Page.captureScreenshot` 全部挂起（已实测）。截图慢（约 15s/张）属本机 GPU 回读特性。
- 共享同一 app 实例的测试套件不得并行运行（状态竞态）。
